{% comment %} Canonical MedicalWebPage for one content page. This is the only place the node is built — schema.html delegates here rather than repeating the template. Params (pass at most one; they select the @type of `about`): condition_name -> MedicalCondition procedure_name -> MedicalProcedure device_name -> MedicalDevice therapy_name -> MedicalTherapy Pass none for listing/hub pages. No `about` is better than a wrong one: the previous version typed everything under /treatments/ as a MedicalCondition named after the page title, so the site asserted in machine-readable form that a pessary and "Watch and Wait" were diseases. reviewedBy/author reference the canonical #physician node from schema.html rather than repeating an inline Physician — see that file for why. lastReviewed is emitted only when the page actually carries a review date, using the same chain as author-card.html so the visible "Medically reviewed" line and the structured data always agree. Do NOT add `| default: page.last_modified_at` to this chain. A file's mtime is not a medical review. Falling back to it made ~40 live pages assert a physician review that never happened, in both the visible byline and the MedicalWebPage JSON-LD. A page with no review date should show no review claim at all. Every interpolated string goes through `| jsonify`, which supplies its own quotes. A title containing an apostrophe or backslash would otherwise emit invalid JSON on 100+ pages. {% endcomment %} {%- assign review_date = page.last_evidence_review | default: page.last_reviewed_date -%} {%- assign page_url = page.url | absolute_url -%} {%- comment -%} Resolve the free-text *_name a page passed into a canonical concept from _data/medical_concepts.yml (T-0027).
